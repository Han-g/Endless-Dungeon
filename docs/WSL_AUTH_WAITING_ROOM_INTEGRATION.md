## 호환성과 운영 정책

- 기존 계정은 비밀번호 재설정이나 DB 변환 없이 사용합니다.
- 기존 환경 변수 이름 MONGODB_DATABASE, REDIS_URL 등을 유지합니다.
- 통합 전 발급한 토큰은 계정별 최신 세션 인덱스가 없어 새 정책에서 거절됩니다. 한 번 재로그인해야 합니다.
- 통합 후 생성한 세션은 Redis 데이터와 TTL이 남아 있으면 인증 서버 재시작 후에도 유효합니다.
- 이미 접속한 클라이언트는 재로그인·로그아웃·만료 시 종료됩니다.
- Pub/Sub 유실은 주기 검사로 보완하고 Redis 장애 시 기존 연결을 닫습니다.
- 계정 비활성화는 로그인과 인증 조회에서 검사합니다. 별도 관리자 API나 계정 상태 실시간 변경 알림은 구현 범위 밖입니다.
- 현재 다중 게임 프로세스나 게임방 복구를 지원한다고 볼 수는 없습니다.

## 검증 기록

- WSL Node.js 22.23.3, Redis 7.0.15, 임시 MongoDB 7.0.24.
- 서버·테스트·부하 테스트 코드 타입 검사 통과.
- 배포용 빌드 통과.
- 규칙/통합 검증 총 27개 항목 통과. 전체 실행에서 26개 통과 후, production 기본 URL의 기대값을 실제 개발 도구 경로 기준으로 보완하고 해당 1개를 재실행하여 통과.
- production의 /monitor, /rooms, /__apidocs가 404이며 health 준비 후 접속 가능함을 확인.
- 기존 WSL 해시와 accountId/status 필드를 사용하는 고정 fixture로 로그인, 프로필 유지, 해시 비변경 확인.
- 다른 인증 인스턴스의 세션 폐기가 실제 WebSocket에 전달되는지 확인.
- Pub/Sub 알림 없는 Redis TTL 만료, 동시 로그인, 이전 토큰 로그아웃, Redis 장애 확인.
- 실사용 계정의 비밀번호를 입력받거나 재설정하지 않았으며 실제 계정 로그인 UI는 조작하지 않음.

실행 상태와 계정 보존의 적용 후 확인 결과는 같은 폴더의 적용 기록에 남깁니다.
