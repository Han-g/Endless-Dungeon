## 주요 구현 선택

1. 계정 ID는 서버 UUID이며 `loginId`에 MongoDB 고유 인덱스를 적용합니다. 동시 중복 가입은 하나만 성공합니다.
2. 비밀번호는 비동기 scrypt (`N=131072`, `r=8`, `p=1`)와 랜덤 salt를 사용합니다. 동시 해시 연산은 2개로 제한합니다.
3. 32바이트 난수 토큰과 2시간 세션을 사용합니다. 서버에는 SHA-256 키를 보관하며 계정별 최신 세션만 유효합니다.
4. 좌석 예약과 실제 WebSocket 참가 사이에 토큰이 폐기될 수 있어 `onJoin`에서 재검사합니다. 연결 중 로그아웃·재로그인·만료도 감시합니다.
5. 게임방 점유는 계정/방/세션 ID가 모두 일치할 때만 해제합니다. 실패한 중복 입장이 기존 참가자의 점유를 해제할 수 없습니다.
6. Ready·시작·로딩 명령은 검사와 변경 사이에 await를 두지 않습니다. 최근 128개 결과를 연결별로 캐시합니다.
7. 로비에는 `setMetadata`로 순서대로 게시하고 시작 순간 방을 잠급니다.
8. 로딩 제한은 방 타이머로 30초입니다. 실제 퇴장은 `onLeave`에서 정리하고 남은 전원의 로딩 여부로 진행합니다.

## 검증 결과

- `npm.cmd run typecheck`: 통과. 서버·테스트·부하 테스트 코드 포함.
- `npm.cmd test`: 19개 통과, 약 18초. 최초 MongoDB 다운로드 시간 별도.
- `npm.cmd run build`: 통과, 배포용 `build/index.js` 생성.
- 컴파일된 진입점을 `MONGODB_URI` 없이 실행: `MONGODB_URI_REQUIRED`, 종료 코드 1 확인.
- 기존 변경·미추적 파일 166개를 보존 기록과 비교: 해시 및 삭제 상태 불일치 없음. 서버와 백업 제외용 루트 `.gitignore` 외에 추가 변경 없음.
- HTTP: 가입·로그인·me 계약, 해시 저장, 동시 중복 가입, 비밀번호 공백, 잘못된 JSON, 요청 제한.
- WebSocket: 미인증/우회 방 거절, 방장 권한·이전, 4인 정원, Ready·캐릭터 변경, 로딩 장벽·30초 제한, 로비 갱신, 토큰 폐기 시 연결 종료.
- 경쟁 상태: 중복 입장 실패 시 기존 점유 유지, 좌석 예약 후 토큰 폐기, 명령 재전송과 요청 ID 재사용 거절.
- 지속성: 세션 만료 알림, 인증 서비스 재시작 후 계정 유지와 기존 세션 폐기.

통합 테스트는 자체 생성한 임시 DB만 사용하고 정리합니다. Node.js 24에서 발생한 CommonJS/ESM 중복 로딩 문제는 테스트 실행 옵션을 ESM으로 통일해 해결했습니다.

Unity 에디터의 실제 UI 조작, 프로덕션 배포, 장시간 부하 측정은 수행하지 않았습니다. 실행과 계정 생성 방법은 서버 README에 있습니다.
